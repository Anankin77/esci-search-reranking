When does keyword matching fail?

Setup in one paragraph

Each query comes with about candidate products that Amazon already retrieved, each labelled by a person as E Exact, S Substitute, C Complement or I Irrelevant. A method gives every (query, product) pair a score; we sort the candidates by score and measure how well the order puts Exact products first (nDCG). The model only sees the query text and the catalog fields — never the labels.

  • Unit of prediction: one (query, product) pair gets a relevance score.
  • Unit of evaluation: one query — the ranked list of its candidates.
  • Limits: we re-rank candidates Amazon already retrieved. We say nothing about Amazon's live search, the retrieval stage, or why people buy.

Preprocessing and features

Text cleaning

  1. Strip HTML tags and entities; Unicode NFKC; collapse whitespace.
  2. Lowercase only inside feature code; original text kept for display.
  3. Truncate description and bullet points to characters (speed).
  4. Tokens: lowercase alphanumeric runs, decimals kept, in-word apostrophes dropped (levi's → levis).

Learned preprocessing stays inside the training fold

BM25 statistics (IDF, average length), the brand vocabulary and the logistic-regression scaler are fit on the training part of each fold only — and on the full training split for the final model. The test split was opened once, after the model was frozen.

Features ()

Every feature is a function of the query and catalog text. None uses relevance labels.

Baselines and methods

Baselines (no learning)

  1. Random order, averaged over 20 seeds — the floor.
  2. BM25 on title — the main baseline (rank_bm25 BM25Okapi, k1 = , b = , IDF from training titles).
  3. BM25 on all fields (title + brand + colour + bullets) — a stronger lexical baseline.
  4. Encoder cosine: zero-shot cosine between query and title embeddings from (released 2021, before ESCI).

Learned models

  1. Logistic regression (pointwise): predicts “Exact vs not”; standardised features; C and class weight tuned.
  2. LightGBM pointwise regression on the gain value (E/S/C/I → 1 / 0.1 / 0.01 / 0).
  3. LightGBM LambdaRank: optimises nDCG directly with the official gains as label_gain; early stopping on an inner split of the fold's training part.

Validation design

5-fold GroupKFold on the training queries, grouped by query so all candidates of a query stay together. Selection rule fixed in advance: highest mean CV nDCG; within 0.002, the simpler model wins (logistic regression < LightGBM pointwise < LambdaRank).

Evaluation

Metrics

  • nDCG (full list, primary) — official ESCI metric; gains E = 1, S = 0.1, C = 0.01, I = 0; discount log2(rank + 1).
  • nDCG@5 — what a shopper sees first.
  • Exact-P@1 — is the first result exactly what was asked for?

Ties in scores are broken with a seeded random key, never row order.

          Limitations

          • Re-ranking only. The candidates were pre-retrieved by Amazon, so retrieval errors are invisible.
          • Noisy labels. Labels are human judgments with noise and ambiguity, especially Substitute vs Exact.
          • Hard subset. The small version was chosen to be difficult, so results do not transfer to typical traffic.
          • English / US only.
          • Shared products across splits ( of test pairs) and near-duplicate queries ( test queries; results shown both ways).
          • Encoder. was released before ESCI (June 2022), so it cannot have been trained on it, but its general web training may still include Amazon-like text. No model fine-tuned on ESCI or e-commerce search was used, and no LLM judged relevance.
          • Explanations ≠ intent. Feature contributions explain the model, not the shopper. Prediction is not causation.
